## System Requirements

### Supported Operating Systems
- **Linux:** Ubuntu 20.04+, Debian 11+, RHEL/AlmaLinux 8+, Raspberry Pi OS (64-bit).
- **Windows:** Windows 10/11, Windows Server 2016, 2019, 2022.

### Hardware Recommendations (Wazuh Manager)
For SMB environments, the Wazuh Manager can be deployed on cost-effective hardware:
- **Recommended:** Raspberry Pi 4 (8GB) or Raspberry Pi 5.
- **Storage:** High-endurance microSD card (Class 10/UHS-I) or ideally a USB 3.0 SSD for better IOPS.
- **Connectivity:** Ethernet connection is strongly recommended over Wi-Fi.

### Network Requirements
Ensure the following ports are open on the Wazuh Manager:
- **1514 (TCP/UDP):** Agent event communication.
- **1515 (TCP):** Agent enrollment.
- **55000 (TCP):** Wazuh API (for management).

## Wazuh Infrastructure Setup

Before deploying agents, the Wazuh Manager must be configured with honeypot-specific decoders and rules.

### 1. Install Decoders
Copy the custom decoders to your Wazuh Manager:
```bash
cp wazuh/decoders/honeypot_decoder.xml /var/ossec/etc/decoders/
```

### 2. Install Rules
Copy the custom rules to your Wazuh Manager:
```bash
cp wazuh/rules/honeypot_rules.xml /var/ossec/etc/rules/
```

### 3. Active Response (Optional)
To automatically trigger a forensic snapshot when a honeypot is accessed:
```bash
cp wazuh/active-response/honeypot-forensic-snapshot.sh /var/ossec/active-response/bin/
chmod 750 /var/ossec/active-response/bin/honeypot-forensic-snapshot.sh
chown root:wazuh /var/ossec/active-response/bin/honeypot-forensic-snapshot.sh
```

### 4. Restart Wazuh Manager
```bash
systemctl restart wazuh-manager
```

## Endpoint Configuration

### Linux Setup

#### 1. Install Auditd
`auditd` is required for high-fidelity "whodata" monitoring and process attribution.
```bash
sudo apt update && sudo apt install auditd -y  # Debian/Ubuntu
sudo yum install audit -y                     # RHEL/CentOS/AlmaLinux
```

#### 2. Configure Wazuh FIM
Add the honeypot monitoring paths to the agent's `/var/ossec/etc/ossec.conf`. You can use the `honeypot-deployer` CLI to generate a localized config snippet:
```bash
honeypot-deployer wazuh-config --manifest ./manifest.json --os linux
```

#### 3. Apply Audit Rules
```bash
sudo cp wazuh/agent-config/honeypot-audit.rules /etc/audit/rules.d/honeypot.rules
sudo auditctl -R /etc/audit/rules.d/honeypot.rules
```

### Windows Setup

#### 1. Install Sysmon (Recommended)
Download [Sysmon](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon) and install it with the provided honeypot configuration:
```powershell
.\Sysmon64.exe -i wazuh\agent-config\honeypot-sysmon.xml
```

#### 2. Configure Wazuh FIM
Edit `C:\Program Files (x86)\ossec-agent\ossec.conf` and add the `<syscheck>` entries generated by:
```bash
honeypot-deployer wazuh-config --manifest .\manifest.json --os windows
```

### Containerized Deployment (Docker)

To run a Wazuh agent inside a container while maintaining high-fidelity monitoring:
1. **Privileged Mode:** The container must be run with `--cap-add=AUDIT_CONTROL` and `--pid=host` to interact with the host's `auditd` kernel interface.
2. **Volumes:** Mount the honeypot artifact directories into the container or deploy them to a shared volume.
3. **Environment:** Set the `NODE_NAME` environment variable to uniquely identify the containerized agent.

## Honeypot Artifact Generation

### Using the CLI (Recommended)
The CLI generates randomized artifacts and tracks them in an encrypted manifest.

```bash
# Install
pip install .

# Generate all supported chains + browser decoys
honeypot-deployer generate --output ./my-honeypots

# View manifest (requires password if encrypted)
honeypot-deployer show --manifest ./my-honeypots/manifest.json
```

### Security: Manifest Encryption
The `manifest.json` contains the private keys for your honeypots. By default, the CLI uses `--encrypt-manifest` to protect this file with AES-256. **Never store the manifest unencrypted in a production environment.**

## Browser Extension Mappings

The honeypot system deploys decoys to the following standard paths to lure infostealers.

| Browser | OS | Path |
|---------|----|------|
| **Chrome** | Linux | `~/.config/google-chrome/Default/Local Extension Settings/` |
| **Chrome** | Windows | `%LOCALAPPDATA%\Google\Chrome\User Data\Default\Local Extension Settings\` |
| **Edge** | Windows | `%LOCALAPPDATA%\Microsoft\Edge\User Data\Default\Local Extension Settings\` |
| **Brave** | Linux | `~/.config/BraveSoftware/Brave-Browser/Default/Local Extension Settings/` |
| **Brave** | Windows | `%LOCALAPPDATA%\BraveSoftware\Brave-Browser\User Data\Default\Local Extension Settings\` |
| **Firefox** | Linux | `~/.mozilla/firefox/*.default*/storage/default/` |
| **Firefox** | Windows | `%APPDATA%\Mozilla\Firefox\Profiles\*.default*\storage\default\` |

*Note: Firefox extensions use the `moz-extension+++` directory naming convention.*

## Deployment Verification

1. **CLI Health Check:**
   ```bash
   honeypot-deployer health-check --manifest ./my-honeypots/manifest.json
   ```
2. **Trigger Test Alerts:**
   - **Linux:** `cat ~/.bitcoin/wallet.dat`
   - **Windows:** `type %APPDATA%\Bitcoin\wallet.dat`
3. **Wazuh Dashboard:**
   Check for alerts with IDs **100501** (File Access) and **100510** (Audit Rule Triggered).
