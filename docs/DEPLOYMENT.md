# Deployment Guide: Crypto Wallet Honeypot

This document provides detailed requirements and step-by-step instructions for deploying the Crypto Wallet Honeypot system with Wazuh SIEM integration.

## 1. System Requirements

### Hardware Recommendations (Wazuh Manager)
For SMB environments, we recommend running the Wazuh Manager on:
- **Raspberry Pi 4 (8GB)** or **Raspberry Pi 5**.
- **Storage:** High-endurance microSD card or USB 3.0 SSD (preferred).

### Supported Operating Systems (Agents)
- **Linux:** Ubuntu 20.04+, Debian 11+, RHEL/AlmaLinux 8+.
- **Windows:** Windows 10/11, Windows Server 2016+.

### Network Requirements
- **Port 1514 (TCP/UDP):** Agent event communication to Manager.
- **Port 1515 (TCP):** Agent enrollment to Manager.

---

## 2. Wazuh Manager Configuration

The Wazuh Manager must be configured with custom decoders and rules to recognize honeypot events.

### 1. Install Decoders
Copy `wazuh/decoders/honeypot_decoder.xml` to `/var/ossec/etc/decoders/`.

### 2. Install Rules
Copy `wazuh/rules/honeypot_rules.xml` to `/var/ossec/etc/rules/`.

### 3. Restart Service
```bash
systemctl restart wazuh-manager
```

---

## 3. Honeypot Artifact Generation

The CLI generates unique, randomized artifacts and tracks them in an encrypted manifest for high-fidelity monitoring and on-chain correlation.

```bash
# 1. Install the tool
pip install .

# 2. Generate artifacts
honeypot-deployer generate --output ./my-artifacts

# 3. View the generated manifest
honeypot-deployer show --manifest ./my-artifacts/manifest.json
```

---

## 4. Wazuh Agent Configuration

### Linux (High Fidelity)
To enable "whodata" monitoring, `auditd` must be installed.

1. **Install auditd:** `sudo apt install auditd -y`
2. **Apply Rules:**
   ```bash
   sudo cp wazuh/agent-config/honeypot-audit.rules /etc/audit/rules.d/honeypot.rules
   sudo auditctl -R /etc/audit/rules.d/honeypot.rules
   ```
3. **Update ossec.conf:** Add the FIM configuration generated by `honeypot-deployer wazuh-config`.

### Windows (Sysmon)
We recommend installing Sysmon for enhanced process visibility.
1. **Install Sysmon:** `Sysmon64.exe -i honeypot-sysmon.xml`
2. **Update ossec.conf:** Add the honeypot directories to the `<syscheck>` section.

## 5. Browser Extension Path Mappings

The honeypot decoys should be placed in the following locations to mimic real wallets:

| Browser | OS | Path |
|---------|----|------|
| **Chrome** | Linux | `~/.config/google-chrome/Default/Local Extension Settings/` |
| **Chrome** | Windows | `%LOCALAPPDATA%\Google\Chrome\User Data\Default\Local Extension Settings\` |
| **Edge** | Windows | `%LOCALAPPDATA%\Microsoft\Edge\User Data\Default\Local Extension Settings\` |
| **Brave** | Linux | `~/.config/BraveSoftware/Brave-Browser/Default/Local Extension Settings/` |
| **Firefox** | Linux | `~/.mozilla/firefox/*.default*/storage/default/` |

## 6. Containerized Deployment (Docker)

To run the Wazuh agent in a container while monitoring honeypot files:

```bash
docker run -d --name wazuh-agent \
  -e WAZUH_MANAGER="manager-ip" \
  -e NODE_NAME="honeypot-node-1" \
  --cap-add=AUDIT_CONTROL \
  --pid=host \
  -v /home/user/honeypots:/mnt/honeypots:ro \
  wazuh/wazuh-agent:4.x
```
*Note: `--cap-add=AUDIT_CONTROL` and `--pid=host` are required for whodata/auditd support inside a container.*

---

## 7. Deployment Verification

1. **Verify Artifacts:** Run the health check command:
   ```bash
   honeypot-deployer health-check --manifest ./my-artifacts/manifest.json
   ```
2. **Trigger a Test Alert:**
   On a Linux agent: `cat ~/.bitcoin/wallet.dat`
   On a Windows agent: `type %APPDATA%\Bitcoin\wallet.dat`
3. **Check Wazuh Dashboard:** Confirm that a Level 12 (or higher) alert appears in the security events.
