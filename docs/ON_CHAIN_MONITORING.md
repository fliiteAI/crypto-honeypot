# On-Chain Monitoring Guide

Layer 4 of the detection strategy involves monitoring the generated honeypot addresses on their respective blockchains. This provides a final "safety net" and absolute confirmation of a compromise.

## How It Works

1. **Generation:** When you run `honeypot-deployer generate`, the tool creates valid (but empty) private keys and their corresponding public addresses.
2. **Manifest:** These addresses are stored in the `manifest.json`.
3. **Export:** You can export these addresses into a simplified JSON format for import into monitoring tools.
4. **Monitoring:** An external monitor (like a block explorer watchlist or a custom script) watches these addresses for any activity.
5. **Alerting:** Any activity (balance query, transfer) triggers an alert in Wazuh.

## Setting Up Watchlists

The easiest way to implement Layer 4 monitoring is using the "Watchlist" feature of major block explorers.

### 1. Export Honeypot Addresses
Run the following command to get a list of all monitored addresses:
```bash
honeypot-deployer export-addresses --manifest ./my-artifacts/manifest.json --output ./watch-list.json
```

### 2. Configure Block Explorers
For each chain, add the exported addresses to a watchlist on a relevant block explorer and configure them to send Webhook or Email notifications.

- **Ethereum (ETH):** [Etherscan.io](https://etherscan.io/) -> My Profile -> Watch List
- **Bitcoin (BTC):** [Blockchain.com](https://www.blockchain.com/explorer) or [Mempool.space](https://mempool.space/)
- **Solana (SOL):** [Solscan.io](https://solscan.io/) or [Solana.fm](https://solana.fm/)
- **XRP:** [XRPScan.com](https://xrpscan.com/)

### 3. Integrating with Wazuh
If the block explorer supports Webhooks, you can point them to a custom listener that forwards the events to the Wazuh Manager as JSON logs. The custom rules in `wazuh/rules/honeypot_rules.xml` (specifically Rule IDs **100530-100533**) are designed to parse these events.

## Why Monitor On-Chain?

- **Anti-Forensics Bypass:** If an attacker manages to clear host logs or disable the Wazuh agent before exfiltrating the keys, on-chain monitoring will still detect the eventual usage of those keys.
- **Attacker Attribution:** On-chain movements can often be traced to centralized exchanges, potentially aiding in the identification of the attacker.
- **Confirmation of Intent:** Accessing a file might be accidental; importing a key into a wallet and querying its balance is a clear demonstration of malicious intent.

## Security Warning
**NEVER** deposit real funds into any address generated by this tool. The private keys are stored in the `manifest.json` on your deployment machine and are considered "hot" keys.
