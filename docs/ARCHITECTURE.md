# Architecture Overview

The Crypto Wallet Honeypot is a multi-layered detection system designed to catch attackers at various stages of the cyber kill chain. By deploying realistic-looking cryptocurrency artifacts and monitoring them with Wazuh SIEM, we achieve high-fidelity alerts with zero false positives.

## Detection Strategy

The system utilizes a 4-layer detection strategy to ensure that even if an attacker bypasses one layer, they are caught by another.

### Layer 1: File Integrity Monitoring (FIM)
- **Mechanism:** Wazuh FIM (syscheck)
- **Goal:** Detect any read, modification, or deletion of honeypot files.
- **Rule IDs:** 100500-100509
- **Description:** This is the primary detection layer. Legitimate users and processes have no reason to access the honeypot files. Any interaction is considered malicious.

### Layer 2: Process and Command Auditing
- **Mechanism:** Linux `auditd` / Windows Sysmon
- **Goal:** Identify the specific process and user accessing the honeypot files.
- **Rule IDs:** 100510-100519
- **Description:** Provides context beyond simple file access. Tracks which command was used (e.g., `cat`, `grep`, `scp`) and which user executed it.

### Layer 3: Network Correlation
- **Mechanism:** Wazuh log analysis & Network monitoring
- **Goal:** Correlate honeypot file access with subsequent network exfiltration.
- **Rule IDs:** 100520-100529
- **Description:** Detects patterns where an attacker reads a wallet file and immediately uses a network tool (like `curl` or `ssh`) or connects to known paste sites/C2 servers.

### Layer 4: On-Chain Monitoring
- **Mechanism:** External block explorer watchlists & On-chain monitoring scripts
- **Goal:** Detect when stolen private keys are imported and used on the blockchain.
- **Rule IDs:** 100530-100539
- **Description:** The ultimate confirmation. If a honeypot address shows activity on-chain, it confirms the credentials were successfully exfiltrated and are being used.

## MITRE ATT&CK Mapping

The detections provided by this system map to the following MITRE ATT&CK techniques:

| ID | Technique | Detection Layer |
|----|-----------|-----------------|
| **T1005** | Data from Local System | Layer 1 |
| **T1070** | Indicator Removal | Layer 1 |
| **T1083** | File and Directory Discovery | Layer 1, 2 |
| **T1555** | Credentials from Password Stores | Layer 1 |
| **T1555.003** | Credentials from Web Browsers | Layer 1 |
| **T1560** | Archive Collected Data | Layer 2, 3 |
| **T1041** | Exfiltration Over C2 Channel | Layer 3 |
| **T1048** | Exfiltration Over Alternative Protocol | Layer 3 |
| **T1657** | Financial Theft | Layer 4 |

## System Design Philosophy

The core philosophy of this project is **Zero False Positives**. Unlike traditional IDS/IPS systems that rely on fuzzy signatures, this honeypot relies on the violation of a "no-go" zone. Since no authorized personnel or processes should ever touch these files, any alert generated by the system is high-fidelity and requires immediate investigation.
