# Architecture Overview: Crypto Wallet Honeypot

This document describes the architectural design, detection strategy, and security principles of the Crypto Wallet Honeypot system.

## Detection Strategy

The system employs a 4-layer defense-in-depth strategy to detect attackers at different stages of the kill chain.

### Layer 1: File Integrity Monitoring (FIM)
The primary detection mechanism uses Wazuh's FIM module. We monitor specific paths where cryptocurrency wallet files are traditionally stored.
- **Mechanism:** Wazuh `syscheck`
- **Events:** File creation (554), modification (550), and deletion (553).
- **Fidelity:** Very high. Legitimate users or processes should never access these decoy files.

### Layer 2: Process Auditing
To provide context on *who* and *how* the files were accessed, we integrate with OS-level auditing tools.
- **Linux:** `auditd` rules monitor read/write access and report user attribution (`whodata`).
- **Windows:** `Sysmon` tracks process creation and file access events, identifying the parent process and command line used to access the honeypot.

### Layer 3: Network Correlation
We correlate honeypot file access with subsequent network activity.
- **Detection:** Identifying outbound connections to common exfiltration targets (paste sites, known C2 IPs, or large data transfers) immediately following a honeypot trigger.
- **Tools:** Wazuh ruleset correlating FIM alerts with network logs (Sysmon Event ID 3 or Linux socket events).

### Layer 4: On-Chain Monitoring
The final layer of detection occurs outside the compromised host.
- **Mechanism:** Public blockchain addresses generated by the tool are added to watchlists on block explorers (e.g., Etherscan, Solscan).
- **Detection:** Alerts are triggered if the "stolen" private keys are imported and used to sign a transaction or if funds are moved to/from the honeypot addresses.

## MITRE ATT&CK Mapping

The honeypot system provides coverage for the following MITRE ATT&CK techniques:

| ID | Technique | Detection Layer |
|----|-----------|-----------------|
| **T1083** | File and Directory Discovery | Layer 1, 2 |
| **T1005** | Data from Local System | Layer 1 |
| **T1555** | Credentials from Password Stores | Layer 1 |
| **T1555.003** | Credentials from Web Browsers | Layer 1 |
| **T1560** | Archive Collected Data | Layer 2, 3 |
| **T1041** | Exfiltration Over C2 Channel | Layer 3 |
| **T1048** | Exfiltration Over Alternative Protocol | Layer 3 |
| **T1657** | Financial Theft | Layer 4 |
| **T1070** | Indicator Removal | Layer 1 |

## Component Diagram

1. **Honeypot Deployer CLI:** Generates randomized artifacts and encrypted manifests.
2. **Monitored Endpoints:** Host the decoy artifacts and run Wazuh Agents.
3. **Wazuh Manager:** Collects logs, processes rules, and triggers alerts.
4. **Blockchain Watchers:** Monitor the public ledger for activity on honeypot addresses.
